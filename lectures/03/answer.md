### 実装：承認付きの学習ログ保存ツールを追加する

- やったこと：
  - `app/tools.py` に `save_learning_log(content: str) -> str` を追加した。`learning_log/` フォルダを作り、`learning_log_YYYYMMDD_HHMMSS_ffffff.txt` という日時入りのファイル名で内容を保存する。
  - `app/agent.py` で `agent.tool_plain(tools.save_learning_log, requires_approval=True)` と登録し、エージェントの `output_type` に `DeferredToolRequests` を加えた。
  - `run_with_approval` で承認待ちのツール名・引数を表示し、利用者の入力を受け取るようにした。`y` / `yes` なら承認し、それ以外は拒否する。承認結果を `DeferredToolResults` にまとめ、それまでの `message_history` と一緒に渡して処理を再開する。
  - 次の質問を `--trace` 付きで実行し、確認画面で `y` を入力した。

  ```bash
  uv run python -m app.agent --trace "学習記録を保存して。内容はLoRAの効率的な計算手法がわかったという感じです。"
  ```

- 結果：
  - 保存処理の前に、次の承認確認が表示された。

    ```text
    save_learning_log の実行が承認待ちです。
    引数: {'content': 'LoRAの効率的な計算手法がわかった'}
    実行を許可しますか？ [y/N]: y
    ```

  - 承認後、`save_learning_log({'content': 'LoRAの効率的な計算手法がわかった'})` の実行結果として、`learning_log/learning_log_20261103_140627_399026.txt` に記録した旨が表示された。エージェントからも保存完了の回答が返った。
  - 自動テストでは、承認時にファイルが作られて内容が保存されることと、拒否時には保存先フォルダが作られないことを確認した。提出前の `uv run --frozen pytest -q` は16件すべて成功した。

- 気づき・疑問：
  - モデルがツールを呼ぼうとすることと、実際にファイルを書き込むことを分けられた。保存する内容を利用者が確認してから実行できる仕組みがHuman-in-the-loopに当たると理解した。
  - 承認後に続きから再開するには、承認・拒否の結果だけでなく、それまでの会話履歴も渡す必要があった。
  - 実行ログ末尾の `[usage]` は `requests=1`、`tool_calls=1` だった。ただし、現在のコードは再開後の最後の実行結果の使用量を表示するため、この `requests` を承認前後の総呼び出し回数とは解釈しない。

### 発展：Google ADK でエージェントを作り直す（a）

- やったこと：
  - `adk_agent/glossary_agent/agent.py` と `__init__.py` を作成し、Google ADK版のエージェントを実装した。

  - ADKを開発依存関係に追加し、`adk run` で対話した。提示した実行ログの質問は「第3回では何を学びますか？」だった。

- 結果：
  - ADK版は重要用語として「AIエージェント」を取り上げ、用語集の定義に基づいて、基本構造が「モデル＋ループ＋ツール」であることを説明した。
